### Finality, validation, and immutable snapshots

Schedule scores/result identify candidates, not final games. Publication requires an explicit last PBP record with `desc = END GAME`, `drive_end_transition = END_GAME`, matching final schedule/PBP scores, all regulation quarters, a game-start marker, valid unique play keys, team/possession checks, and scoring-event reconstruction. Missing or ambiguous records stay unpublished. This conservative gate can decline a completed game with an unusual or revised source representation; it does not infer completion from elapsed time. Overtime can be ingested, while individual models separately reject unsupported overtime states.

The worker's store permits only known nflverse GitHub release paths and GitHub release-CDN redirects. It retains original bytes, source URL, UTC retrieval time, SHA-256, source Last-Modified/ETag, license, attribution, and snapshot ID. Conditional requests and a per-source cache avoid repeated season downloads. The per-URL index may advance; content-addressed snapshot bytes do not change. An analysis revision records the exact consumed snapshots and model artifacts. Download modification times are artifact freshness, not necessarily the time of the latest game or individual correction.

## Data licenses are separate from software licenses

- nflverse-data and nflverse-pbp repositories publish a [CC BY 4.0 data notice](https://raw.githubusercontent.com/nflverse/nflverse-data/main/LICENSE.md). Attribute **nflverse / nflfastR**, link the source and license, preserve supplied notices, and indicate transformations. Schedules additionally credit **Lee Sharpe**. [nfldata](https://github.com/nflverse/nfldata) itself has no detected license file or repository-license metadata; the application uses the schedule release published by nflverse-data and records this provenance, rather than inventing an MIT data license.
- FTN charting has its own **[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)** terms, overriding general repository assumptions. Credit **FTN Data via nflverse**. Redistributed adapted FTN charting material, including the extracted FTN fixture files and FTN-derived tabular exports, retains that license, attribution, modification notice, and applicable share-alike requirements. This is not a claim that all independent application source code must take the dataset license. The report data-sources page and FTN evidence must carry the attribution and license link.
- [nflreadr software](https://raw.githubusercontent.com/nflverse/nflreadr/main/DESCRIPTION) and [nflfastR software](https://raw.githubusercontent.com/nflverse/nflfastR/master/DESCRIPTION) are MIT plus their LICENSE files. The MIT package license does not license every underlying dataset. [nflverse terms](https://nflverse.nflverse.com/#terms-of-use) distinguish source owners' terms from software licensing.
- No source license here grants rights to league/team trademarks or third-party video. Use text team abbreviations and evidence links; do not mirror video or team logos. Rulebook references are links and concise rule citations rather than a redistributed rulebook.

## Established analytics and rule references

The R runtime pins nflfastR **6.0.0**, nflreadr **1.5.0**, fastrmodels **2.1.0**, nfl4th **1.0.7**, and raw-player-ID decoder gsisdecoder **0.0.1**. Consult the R dependency lock and artifact manifests for exact resolved dependencies and checksums. The actual cached `2023_01_DET_KC.rds` (SHA-256 `fe5f322f9260cc83b280194a120a06b254fce9fd9d425c97653e4e4847e2db13`) successfully built through `run.R` with `decode=TRUE`: 179 rows, terminal play 4226, `END GAME`. The immutable local tree is `<rawDirectory>/<season>/<game_id>.rds`.

- State calculators: [calculate_win_probability](https://nflfastr.com/reference/calculate_win_probability.html), [calculate_expected_points](https://nflfastr.com/reference/calculate_expected_points.html). Officiating comparisons use the same named team and explicitly labeled, non-spread WP family. Immediate scoring and continuation value must be reconciled separately for EP.
- [nflfastR model methodology](https://opensourcefootball.com/posts/2020-09-28-nflfastr-ep-wp-and-cp-models/) describes exclusions for tied final games/overtime and leave-one-season-out evaluation. Those are not evidence of leakage-free chronological evaluation of the currently distributed artifacts. A complete current training cutoff was not established; third-party-model provenance limitations remain visible. Ingesting a tied/OT game does not make a regulation counterfactual model valid there.
- Fourth down: [nfl4th](https://www.nfl4th.com/), versioned [helpers](https://raw.githubusercontent.com/nflverse/nfl4th/v1.0.7/R/helpers.R), [WP application](https://raw.githubusercontent.com/nflverse/nfl4th/v1.0.7/R/apply_win_prob.R), [decision functions](https://raw.githubusercontent.com/nflverse/nfl4th/v1.0.7/R/decision_functions.R), and [wrapper](https://raw.githubusercontent.com/nflverse/nfl4th/v1.0.7/R/wrapper.R). Official archived artifacts: [fourth-down model](https://github.com/nflverse/nfl4th/releases/download/model_archive/fd_model.rds), [WP model](https://github.com/nflverse/nfl4th/releases/download/model_archive/wp_model.rds). Preserve the upstream MIT notices for vendored code and document every modification.
- The project fork `under-review-nfl4th-2026-v1` injects frozen models/schedules and parametrizes kickoff continuation, elapsed time, and timeouts. Its recorded 2025/2026 coaching gate passed ten diagnostics. In-domain regulation estimates that pass the kickoff-sensitivity checks can be supported as model-relative comparisons; sensitive decisions remain experimental. This does not establish a known upstream training cutoff or universal modern-rule validity.
- Rules: [NFL rulebook landing page](https://operations.nfl.com/the-rules/nfl-rulebook/), [2026 rulebook PDF](https://static.www.nfl.com/image/upload/fl_attachment/league/tqivdkzt9mu6wdgsh1ku.pdf). Reviewed calls must cite their actual rule season. In particular, 2026 Rule 6-1-5 distinguishes the receiving team's 35-yard-line direct-end-zone touchback from 20-yard-line outcomes after a landing-zone touch or a kick from the 50. Generic kickoff continuation must not silently assume a historical 25-yard line.

Fumble, kicking, and called-penalty baselines are locally trained artifacts with recorded chronological windows and evaluation diagnostics. Dataset descriptions establish available columns, not predictive validity. Out-of-domain states, absent promoted artifacts, and unvalidated overall percentiles remain unavailable; no binary FTN tag is a calibrated probability.

## X publishing integration

| User authorization | [OAuth 2.0 authorization-code flow](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code): confidential web application, PKCE S256, user-context scopes `tweet.read tweet.write users.read offline.access`; token and refresh endpoint `https://api.x.com/2/oauth2/token`. | Reconcile an uncertain submission | [Get Post by ID](https://docs.x.com/x-api/posts/get-post-by-id): `GET /2/tweets/{id}?tweet.fields=author_id,entities`. Verify the intended author, full text, and original report URL using returned URL entities. A missing post does not authorize a resend. |
| Authentication rejection | [Response codes](https://docs.x.com/x-api/fundamentals/response-codes-and-errors): an explicit 401 is an authentication rejection. Refresh at most once and queue a distinct recorded attempt; never apply that path to ambiguous POST failures. |
| Character limits | [Counting characters](https://docs.x.com/fundamentals/counting-characters): 280 weighted characters, URLs weighted as 23, Unicode NFC handling; use the official twitter-text parser rather than JavaScript string length. |
| Access and billing | [Pricing](https://docs.x.com/x-api/getting-started/pricing): API access uses paid usage/credits. Local development does not purchase credits or assume free access. |
| Rate limits | [Rate limits](https://docs.x.com/x-api/fundamentals/rate-limits): respect response headers and 429; maintain persistent retry state. |
| Automation policy | [X automation rules](https://help.x.com/en/rules-and-policies/x-automation): use supported API publishing; no browser-posting automation, unsolicited replies, or engagement/spam automation. |

No real X post is sent by setup verification or tests. Default mode is draft-only, live posting disabled. Automatic posting requires authenticated operator activation for the intended account, a public reachable report URL, a durable outbox, and the global kill switch. No X credentials are required for local ingestion, analysis, reports, or drafts.
